# セットアップ

**相手はターミナルを一度も触ったことがない前提で話す。専門用語を使わず、押すボタンの名前で言う。**
**途中で「進めてよいですか」と聞かない。**詰まったところだけ報告する。

🔴 **この手順の実行中は秘密鍵を確認しない。**
新メンバーのマシンに鍵が無いのは**正常**（→ `${CLAUDE_PLUGIN_ROOT}/skills/setup/access_model.md`）。
確認すると手順が止まり、「自分の環境は欠けている」と誤解させる。**報告する表にも鍵の行を出さない。**

## 1｜現状を見る

```bash
bash "${CLAUDE_PLUGIN_ROOT}/skills/setup/check_setup.sh"
```

**❌ と ⚠️ の両方に対応する。**⚠️（とくに PATH）を無視すると、次にターミナルを開いたとき `claude` が起動しない。

🔴 **自分で埋めてはいけない ❌ が2つある。**

| ❌ | なぜ自分で直せないか | どうする |
|---|---|---|
| **`git`** | `xcode-select --install` は GUI を出して即戻る。**「実行しました」と言えてしまうのに終わっていない** | 本人に画面の指示を終わらせてもらい、`git --version` が返るのを確認してからやり直す |
| **`git の名乗り`** | ヒントの `自分@hicard.studio` は**プレースホルダ**。そのまま登録すると全員が同じ偽アドレスになる | **未設定のときだけ**本人に聞いて設定する |

🔴 **すでに設定されている名乗りは、会社アドレスでなくても触らない。**
**「hicard のアドレスに直しますか」と聞かない。**GitHub の名乗りを変えたくない人が多い。
**Google の認可アドレスとは別の話。混ぜない。**git の名乗りが個人アドレスでも、Drive の認可が正しければ**それで正しい。**

### `hicard プラグイン` が ❌ のとき

```
/plugin marketplace add hicard-inc/claude-plugins
/plugin install hicard@hicard-plugins
```

そのあと **Claude Code を再起動する**（`/exit` → `claude` → `/setup`）。
**入れただけでは skill と MCP は差し替わらない。**再起動まで見届けて、初めて次へ進む。

## 2｜Notion をつなぐ

ツールは遅延ロードのことがある。**呼ぶ前に読み込む**：

```
ToolSearch  query: "+notion search recent pages"
```

| 状態 | 判定 | やること |
|---|---|---|
| 一覧が返る | 繋がっている | 3 へ |
| 読み込めたが認証エラー | **未認可** | 下の案内を出して待つ |
| `ToolSearch` でも出てこない | **プラグインが未導入か未再起動** | 1 の `/plugin install` に戻る |

**この2つを取り違えない。**認証エラーは本人が直せる。ツールが無いのは本人には直せない。

> **表示された URL を開いて、Notion へのアクセスを許可してください。**
> **ワークスペースを選ぶ画面が出たら、必ず「hicard」を選んでください。**
> 個人のワークスペースを選ぶと、繋がったのに hicard のページが1つも見えなくなります。

## 3｜Google ドライブをつなぐ

🔴 **本人にも管理者にも「どのアドレスですか」と聞かない。自分で調べる。**
聞いた時点で手が止まり、返事待ちになる。**Notion は 2 で通っているので、そこから引ける。**

### 3-1. その人の会社アドレスを自分で調べる

Notion の `notion-get-users` を `user_id: "self"` で呼ぶ。
返る形：`{"type":"person","id":"...","name":"<氏名>","email":"<アドレス>"}`

| self の email | どうする |
|---|---|
| **`@hicard.studio`** | **それが第一候補。**以下ずっとこのアドレスを名指しで使う |
| 個人アドレス（Notion も個人で入っている） | 返ってきた `name` で引き直す → `notion-get-users query: "<name>"`。`@hicard.studio` の行を採る |
| どちらでも見つからない | **そのときだけ**本人に「hicard のメールアドレスは何ですか」と1問聞く |

🔴 **`@hicard.studio` が常に正解とは限らない。**Drive 側を**個人 Gmail で招待されている人が実在する**。
3-3 の実測が 3-1 と食い違ったら、**3-3（実際に権限がある方）を信じる。**

**以降、`＿＿＿@hicard.studio` と伏せずに、調べた実物のアドレスを本人に見せて言う。**

### 3-2. すでに繋がっているかを先に見る（🔴 「有効にしてください」から入らない）

**間違ったアカウントで**すでに繋がっている人がいる。
その人に「有効にして許可してください」と言うと「**もうやりました**」と返ってきて、1往復ムダになる。

Drive の検索ツールを `ToolSearch` してから、**まず 3-3 を測る。**
**ツールが認証エラーを返したときだけ**、表示された認可 URL を渡し、こう伝える：

> 🔴 **アカウントを選ぶ画面で、必ず `<3-1 で調べたアドレス>` を選んでください。**
> そのまま進むと、**ブラウザにログイン中のアカウント（＝普段使っている個人の方）で通ります。**

### 3-3. 🔴 判定の前に、必ず認可アカウントを読む（落ちてからでは遅い）

Drive の検索ツールを `query: "owner = 'me'"` `pageSize: 1` で呼ぶ。
返ってきた `owner` が、**いま認可されている Google アカウント**。

**これは 4 で落ちたときの調査ではない。繋がったと分かった時点で毎回やる。**
先に読めば、**本人が「終わった」と思う前に**、名指しで直せる。

| 結果 | 判定 |
|---|---|
| `owner` が 3-1 のアドレスと**違う** | 4 に進む前に、まず 4 の実物判定を試す。**hicard の中身が読めるなら、そのアカウントが正しい**（個人 Gmail で招待されている場合）。読めなければ繋ぎ直し（→ `troubleshooting.md`） |
| `owner` が 3-1 のアドレスと**同じ** | アカウントは合っている。4 へ進む。**そこで落ちたら `all@hicard.studio` に入っていない**（本人から管理者へ依頼。ここでは直せない） |
| **0件**（そのアカウントがファイルを1つも持っていない） | 判定できない。**4 の実物判定に任せる** |

繋ぎ直しの手順と、**繋ぎ直しで本人が失うもの**は `troubleshooting.md` の「Google アカウントの繋ぎ直し」にある。
🔴 **繋ぎ直しを頼む「前」に、失うものを自分から言う。**聞かれてから答えると、
**本人は「黙って不便にされた」と受け取る。**

## 4｜本当に読めるか確かめる（合否は下の基準で決める）

🔴 **「接続済み」「Connected」を合格の理由にしない。**
**繋がっていること自体は、いつでも成立してしまう。**見るのは繋がりではなく、**hicard の中身が返ってきたか**だけ。
過去に、**個人ワークスペースに繋がっている状態を「✅ 接続済み」と報告した**事故が出ている。

**✅ を書くときは、必ず「何が読めたか」を隣に書く。書けないなら、それは ✅ ではない。**

| 書き方 | 可否 |
|---|---|
| `✅ Notion 接続済み` | ❌ **禁止。**何も確かめていない |
| `✅ Notion 接続済み（"<本人の名前>" のワークスペース）` | ❌ **不合格の記述。**hicard でない時点で落ちている |
| `✅ Notion  hicard ワークスペースの「議事録」が読めた` | ⭕️ |
| `✅ Drive  共有ドライブ 001_hicard の 01_Projects が見えた` | ⭕️ |

**🔴 ワークスペース名が `hicard` でなければ、その時点で不合格。**
本人の名前・ニックネームのワークスペースは、**認可の画面で個人側を選んだときの典型的な結果**。2 に戻って選び直してもらう。

### Notion

Notion の検索か最近のページ一覧を呼び、**返ったページを本人に見せる。**

- **合格**：hicard ワークスペースのページが1件以上
- **不合格**：0件、または個人のページだけ → 2 のワークスペース選択が違う

### ドライブ（🔴 「最近のファイル」で判定しない）

「最近見たファイル」を返すツールは、**正しく設定できている新メンバーでも0件になる。**
0件を不合格の根拠にしない。**検索ツールで名前を指定して引く。**

Drive の検索ツールを `query: "title = '01_Projects'"` で呼ぶ。

- **合格**：共有ドライブ `001_hicard` 配下のものが返る
- **不合格**：無い → `all@hicard.studio` に入っていないか、別アカウントで許可した
  → 本人から管理者へ「`all@hicard.studio` に入っていますか。どのアドレスで招待しましたか」

### 片方だけ通ったとき

**完了と言わない。**通った方と通らなかった方を分けて伝え、原因と次の一手を言う。

## 5｜再起動が要るとき

> 1. `/exit` と打って Enter（反応しなければ Esc → それでも駄目なら Control + C を2回）
> 2. `claude` と打って Enter
> 3. 立ち上がったら **`/setup`** と打つ

**再起動後の自分は前の話を覚えていない。**1 から読み直してよい（何度やっても壊れない）。
**ただし 4 の「本人に中身を見せる」は必ずやり直す。**

🔴 **「続き」という言葉を使わせない。**別の作業の合図と衝突する。

## 6｜完了を伝える（4 が両方合格したときだけ）

🔴 **まず、この1行を出す。**本人はこれを Slack に貼るだけで報告が済み、
**管理者は中身を読まずに合否が分かる**（アドレスが妥当か・Drive の行があるか）。

```
✅ セットアップ完了  <名前> / <3-3 で読んだ認可アドレス> / Notion:<読めたページ名> / Drive:01_Projects / <YYYY-MM-DD>
```

🔴 **実際に読めたものの名前を入れる。**入れられないなら、それは完了していない。
**「接続済み」「OK」などの語で埋めない。**

そのあとに、本人向けの案内を出す：

```
セットアップ完了です。

できること：
- hicard の Notion を読む
- hicard の Google ドライブ・スプレッドシートを読む

使い方：
- 始めるとき  ターミナルで claude
- あとは普通に話しかけてください。保存も共有も私がやります

月に1回くらい  /plugin update hicard@hicard-plugins  を実行してください（新しい手順が入ります）。
```

表に無い症状なら、推測で答えず管理者に回す。
