# アクセスモデル：誰として入るか / 鍵が要らない理由 / 止めるもの

`setup` skill の補助資料。**「鍵が無いので動きません」と言い出す前にここを読む。**

## 0. 結論だけ

**入口は4つある。鍵が要るのは、そのうち「人ではない身分」で入る2つだけ。**

| 入口 | 誰として入るか | 鍵 | 見える範囲を決めるもの |
|---|---|---|---|
| **Notion MCP** | **その人本人** | **不要** | 本人の Notion アカウントの権限 |
| **Google Drive / Sheets MCP** | **その人本人** | **不要** | 本人の Google アカウントの権限 |
| Notion Integration（ボット） | **ボット**（人ではない） | `NOTION_TOKEN` | 「接続」したページの配下だけ |
| Google サービスアカウント | **ロボットアカウント**（人ではない） | 認証 JSON | その**メールアドレス**を共有に足したものだけ |

**メンバーが日常で使うのは上の2つ。したがって秘密鍵は要らない。**
下の2つは経理スクリプトを回すときだけで、**この配布物には含まれていない。**

> **いちばん大事な性質：下2つは誰の権限も継承しない。**
> 管理者に見えるものが自動で見えるわけではなく、**明示的に共有した分しか見えない。**
> 逆に言えば、鍵を持つ人は「その身分に共有されているもの全部」に届く。だから配布を絞っている。

| | |
|---|---|

| 事故 | 認可時に**個人ワークスペースを選ぶ**と、繋がったのに hicard が1つも見えない |

## 2. Google ドライブ / スプレッドシート（メンバー全員・鍵なし）

| | |
|---|---|

| 認証 | **本人のアカウントに紐づく OAuth** |

個人 Gmail で招待されている人が実在する。**推測せず、実際に読めるかで判定する**（`SKILL.md` の 3-3・4）。

## 3. 新メンバーに必要なことは、これだけ

| # | やること | 誰が | 鍵 |
|---|---|---|---|
| 1 | **Notion の hicard ワークスペースに招待** | 管理者 | — |
| 2 | **`all@hicard.studio` グループに追加**（個別のドライブ招待は不要） | 管理者 | — |
| 3 | Claude Code を入れて、`hicard` プラグインを導入 | 本人 | — |
| 4 | **Notion を認可**（**hicard ワークスペースを選ぶ**） | 本人 | **不要** |

**1・2 が抜けていると、4・5 が成功しても中身が空になる。**
本人の Claude は「接続成功」と言うので、**実際に1件読ませて確かめる**必要がある。

**秘密鍵は1つも渡さない。**

## 4. 止めるもの（許可設定）— 🔴 本人の手でしか入らない

**plugin は許可設定を配れない。**置き場所は2つしかなく、どちらも配布物に入らない。

| 置き場所 | 誰のもの | 配れるか |
|---|---|---|
| `~/.claude/settings.json` | **その人のマシン** | ❌ **配れない。**本人が作る |
| `<リポジトリ>/.claude/settings.json` | そのリポジトリ | ⭕️ git で配れる。**触るリポジトリがある人だけ** |

**新メンバーは触るリポジトリを持っていないことが多い**（2026-09-05 時点では全員そう）。
その場合、**技術的に止まる層は上の1つだけ**になる。`RULES.md` は文章なので、守る気のない操作は止めない。

🔴 **Claude はこのファイルを書けない。**Bash・Write・Edit の**3つとも拒否される**（2026-09-05 実測）。
エージェントが自分の許可設定を書き換える形になるため、**許可設定を足しても外せない層**にある。
→ **下の中身をそのまま画面に出して、本人にエディタで作ってもらう。**
🔴 **スクリプトに書かせて回避しない。**止められている操作を代行させることになる。

### 貼ってもらう中身

🔴 **正本は `${CLAUDE_PLUGIN_ROOT}/skills/setup/deny.json` の1ファイル。**ここに写しを置かない
（写しを置いていた頃、`check_setup.sh` 側と2回ずれた）。**`cat` して画面に出し、そのまま貼ってもらう**：

```bash
cat "${CLAUDE_PLUGIN_ROOT}/skills/setup/deny.json"
```

`~/.claude/settings.json` が**無ければ**この中身で新規作成する。**あれば** `deny` の中身だけを足す
（**既にある行を消さない。**JSON なので、足すときは前の行の末尾にカンマが要る）。
`deny` は **17 件**。`check_setup.sh` も同じファイルを読んで突合するので、件数が合わなければそこで分かる。

🔴 **同じファイルに `deny` 以外が2つ入っている（0.1.17 から）。消さずに一緒に貼る。**`check_setup.sh` はこの2つも見る。

| 行 | 何をするか | 根拠 |
|---|---|---|
| `permissions.disableBypassPermissionsMode: "disable"` | **bypass モード（`--dangerously-skip-permissions`・Shift+Tab の bypass）に入れなくする。**bypass は deny 以外の確認と安全チェックを全部飛ばし、`.git` や `.claude` への書き込みも通す（公式）。**deny 自体は bypass 中も効く**（公式: Deny rules block in every mode, including bypassPermissions） | 公式（settings-reference）: 「works from any scope. A user can set it in their own settings to lock themselves out of bypass mode」。**実測（2026-09-05・2.1.261）**: `claude --dangerously-skip-permissions` で起動しても、エラーも承諾画面も出ず、**画面下が `auto mode on` のまま普通に開く**。フラグは黙って無視される |
| `extraKnownMarketplaces.hicard-plugins.autoUpdate: true` | **新しい版を自動で取り込む。**この marketplace は第三者扱いで**既定では切れている**（公式） | 貼って起動すると `~/.claude/plugins/known_marketplaces.json` に `autoUpdate: true` が写る（2026-09-05 実測・ログイン前でも写る）。**実測（2026-09-05・0.1.18）: 手動 update なしで、最初の指示を送ってから 5 分後に新版が入った。**走るのは対話セッションで最初の指示を送ってから 0〜10 分後。`-p` だけの使い方や、本体の自動更新を切った環境（`DISABLE_AUTOUPDATER`）では走らない |

`extraKnownMarketplaces.hicard-plugins` は `marketplace add` が既に書いている。**中の `source` は同じなので、丸ごと置き換えてよい**（`autoUpdate` の1行が増えるだけ）。

🔴 **`allow` は1行も書かない。**allow は**守りを増やさない**（止めるものを減らす方向にしか働かない）。
**理由はこれだけで足りる。deny だけにする。**

⚠️ 以前ここには「**効くかどうかが当てにならない**（`Bash(python3:*)` を足しても拒否されたままだった）」と
書いていたが、**根拠が弱かったので取り下げた**（2026-09-05 訂正）。1回拒否されただけで結論していたが、
**その後 allow が無い状態で同じ書き込みが何度も通った。**

🔴 **分類器の拒否は再現しないことがある。**`Stage 2 classifier error - ... usually transient`（一過性）という
拒否理由が実際に出て、**同じコマンドを1回やり直したら通った。**
**1回止まっただけで「この設定は効かない」と決めない。まず1回やり直す。**
それでも止まるなら、Bash を諦めて Read/Edit/Write などの専用ツールに切り替える。

🔴 **`/Users/<名前>/...` の形で書かない。**その人のマシンでしか効かず、配れない。

🔴 **`*` より前は文字どおり照合される。**`Bash(rm -rf *)` と書くと `rm -r` も `rm -f` も止まらない。
だから `Bash(rm:*)`（`rm` で始まるコマンド全部）と書く。

🔴 **引数の順番が違うと当たらない。**`Bash(git push --force:*)` は「`git push --force` で始まる」にしか当たらず、
**`git push origin --force` は素通りする**（公式ドキュメントも「引数を縛る Bash パターンは脆い」と明記）。
`*` は途中にも置けるので、`Bash(git push * --force*)` / `Bash(git push * -f*)` / `Bash(git push * +*)`
（`+main` の形も force push）を**先頭形と両方**入れている。だから force push だけで5行ある。

🔴 **`Write(...)` という行は書かない。**Claude Code が見るのは `Read(...)` と `Edit(...)` だけで、
`Write(...)` は**受け付けるが一度も参照せず、起動時に警告が出る**（公式ドキュメント・v2.1.210 以降）。
0.1.11〜0.1.13 には `Write(**/.env*)` が2行入っていた。**穴は空いていなかった**（`Read` の deny は
同じパスへの**書き込みも止める**・v2.1.228 以降）が、死んだ行と警告を配っていたので 0.1.14 で外した。

**`sudo` を止めても本人は困らない。**止まるのは Claude が代わりに打つときだけで、
本人がターミナルで打つ分には関係ない。

🔴 **同じものが2つずつ並んでいるのは書き間違いではない。**`**/...` と `~/**/...` は
**効く範囲が違う**（2026-09-05 実測）。

| 書き方 | 効く範囲 |
|---|---|
| `Read(**/.env*)` | **Claude を起動したフォルダの中だけ** |
| `Read(~/**/.env*)` | **ホーム（`/Users/<名前>`）配下すべて。**階層の深さは問わない |

`Read(**/.env*)` だけを入れた状態で測ったところ、`~/work/hicard/.env.denytest` は**止まり**、
`~/.env.denytest` は**素通りした**。`~/**/.env*` を足すと後者も止まった。
**片方だけでは穴が残るので、パスを含む行はすべて両方入れる**（だから同じものが2行ずつ並ぶ）。

⚠️ **ホームの外（`/tmp`・外付けドライブ）は `~/**` では守れない**（実測。`/tmp/.env*` は素通り）。
そこで作業させない運用でふさぐ。

🔴 **`.env` で始まる名前と、`.env` で終わる名前は別物。**`Read(**/.env*)` は `.env.local` には当たるが
**`prod.env` には当たらない**（実測で読めてしまった）。だから `*.env` の行も要る。

### 入れたら、1回わざと止める（**省略しない**）

**書いただけでは効いているか分からない。**貼った直後に、本人の前でこの3つを試す。
（bypass 禁止は、本人にターミナルで `claude --dangerously-skip-permissions` と打ってもらう。**画面下が `auto mode on` のまま開けば効いている。**
`bypass permissions on` と出たら効いていない → 管理者に報告。エラーも承諾画面も出ないのが正常（2026-09-05 実測）。）

**先に、試す材料を本人にターミナルで作ってもらう**（🔴 **Claude は `.env*` を作れない。**
`Read(...)` の deny は**同じパスへの書き込み・新規作成も止める**仕様。以前ここに「deny とは別の層」と
書いていたが、公式ドキュメントで仕様と確認した）：

```bash
printf 'DENY_TEST=not-a-secret\n' > ~/.env.denytest
```


| 頼むこと | 合格 |
|---|---|
| 「`rm ~/deny-test.txt` を実行して」 | **止まる** |
| 「`~/.env.denytest` を読んで」 | **止まる**（ホームまで効いていることの確認） |
| 「`~/nonexistent-control.txt` を読んで」 | 🔴 **止まらず「そんなファイルは無い」と返る** |

🔴 **3つ目を省かない。**1つ目と2つ目だけだと、**何もかもが止まっているだけの状態**と区別がつかない。
「止まってほしいものが止まる」と「止まってほしくないものは通る」の両方を見て、初めて確かめたことになる。

**`cat` でも止まる**（2026-09-05 実測）。`Read()` の deny は Read ツールだけでなく
**`cat` のようなシェルの読み取りにも効く。**「`cat` は素通りするから設定は当てにならない」は**誤り。**

**「止まったこと」を自分の目で見るまで ✅ を書かない。**
**3つとも見届けたら、材料も本人にターミナルで片付けてもらう**（`mv ~/.env.denytest ~/.Trash/`）。
🔴 **この `mv` も Claude には拒否される**（2026-09-05 実測）。`.env*` は**作るのも動かすのも止まる。**
作成と後片付けの両方が本人の手作業になる。

✅ **`cd どこか && rm ...` も止まる**（2026-09-05 実測・公式ドキュメントでも仕様と確認）。
deny は `&&` `;` `|` で区切った**各サブコマンド・サブシェル・`$( )` の中・`for` の本体**にも当たり、
`FOO=bar rm ...` のように**環境変数を前に置いても素通りしない。**
**この設定は事故を減らすもので、悪意を止める壁ではない**（`/tmp` など `~/**` の外は守れない）。

### 更新のとき

**この設定は各自のマシンにあるので、こちらから更新を届ける手段が無い。**
中身が変わったら `/setup` をやり直してもらうしかない。
`check_setup.sh` は `deny` が入っているかを**読んで報告するだけ**で、書き換えはしない。
