# GitHub 入門

`setup` skill の補助資料。**Git と GitHub を触ったことがない人に説明するときに読む。**
ここには GitHub そのものの話だけを置く（どのリポジトリをどう運用するかは会社ごとに違うので書かない）。

---


## 1. Git と GitHub は別物

| | 何か | どこにあるか |
|---|---|---|
| **Git** | **変更の履歴を記録する仕組み** | **自分のパソコンの中** |
| **GitHub** | **その履歴を置いて、全員で共有する場所** | インターネット上 |

**Git は仕組みの名前、GitHub はサービスの名前**。Git は1人でも使えるが、
**GitHub は「みんなで同じものを触る」ためのサービス**で、Microsoft が運営している。
同じことをする別のサービスに GitLab や Bitbucket があり、**中身の Git は同じ**。

## 2. 何が嬉しいか

普通のクラウドストレージにファイルを置くのと違うのは、**履歴の残り方**。

| | |
|---|---|
| **誰が・いつ・どこを変えたかが1行単位で残る** | 「このルール、いつ誰が足したんだっけ」が全部たどれる |
| **前の状態にいつでも戻せる** | 消してしまっても戻る |
| **2人が同時に同じファイルを直せる** | 後から突き合わせられる。上書きで消えない |

**「最新版.docx」「最新版_修正.docx」が生まれない**、と考えると近い。

## 3. 基本の流れ

1つの変更が本体に入るまで、次の順に進む。

| 順 | やること | 言い方 |
|---|---|---|
| 1 | 置き場を自分のパソコンにコピーする | **clone**（最初の1回だけ） |
| 2 | 作業用の枝を作る | **branch** |
| 3 | 変更に名前を付けて記録する | **commit** |
| 4 | 枝をインターネット側に送る | **push** |
| 5 | 「この枝を本体に入れてください」と申請する | **Pull Request（PR）** |
| 6 | 本体に入れる | **merge** |

**枝を作るのは、本体を壊さずに試すため**。失敗しても枝を捨てれば本体は無傷。

## 4. かたちは「枝分かれと合流」

Git の履歴は**1本の線ではなく、枝分かれして、また合流する**。

```
main    ●──●──●──────────●──●        ← 本体。全員が見ているのはここ
             ╲          ╱
枝            ●──●──●──●             ← 作業用の枝（誰かが作業中）
                      ╲
枝2                    ●──●──…       ← 別の人の枝。同時に伸びていい
```

- **枝を切る** … 本体から分かれて、自分の作業場所を作る
- **合流する（merge）** … 終わった枝を本体に戻す

**同時に何本でも枝が伸びていい**。だから、**同じ資料を2人が同時に直しても、後から合流できる**。

> **これはエンジニアだけの道具ではない**。あらゆる開発の現場で使われていて、
> **デザイナーも「いま何本の枝が動いているか」を読めると仕事がしやすくなる**。

## 5. 言葉

| 言葉 | 意味 |
|---|---|
| **repository（リポジトリ）** | 置き場そのもの |
| **clone（クローン）** | 置き場を自分のパソコンにコピーすること |
| **pull（プル）** | 手元を最新にすること |
| **commit（コミット）** | 変更に名前を付けて記録すること |
| **branch（ブランチ）** | 作業用の枝 |
| **push（プッシュ）** | 枝をインターネット側に送ること |
| **Pull Request（プルリク・PR）** | 本体に入れてくださいという申請 |
| **merge（マージ）** | 本体に入れること |
| **main（メイン）** | 本体。**全員が見ているのはここ** |
