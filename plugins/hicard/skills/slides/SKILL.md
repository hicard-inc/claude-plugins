# スライドを1本作る: $ARGUMENTS

**2026-08-28 に「明日から使える料理のテクニック」を1本作って確定した手順。**
正本の作例は `${CLAUDE_PLUGIN_ROOT}/skills/slides/example/cooking_techniques.md` と `${CLAUDE_PLUGIN_ROOT}/skills/slides/example/cooking_techniques.html`。
**新しいスライドは、この2つを写して始める**。ゼロから書かない。

---

## 工程は3つ。切れ目で必ず見せる

| # | やること | 出すもの |
|---|---|---|
| **1** | **構成を作る** | `docs/slides/<なまえ>.md` |
| **2** | **ビジュアライズ** | `docs/slides/<なまえ>.html` ＋ Artifact のリンク |
| **3** | **添削を受ける** | diff を読んで反映 |

🔴 **1が終わったら止めて見せる**。2に進むのは、構成に OK が出てから。
**構成が変わると HTML を全部作り直すことになる。**

---

## 1. 構成を作る

### 元ネタは箇条書きで来る

Google Docs の入れ子リストを貼られることが多い（画像で来ることもある）。
**インデントの深さが、そのまま章立て・スライド・行の3階層になっている。**

```
● 超助かるのに誰も言ってない情報   ← 資料全体
  ○ 生肉には塩を振れ              ← 章（＝1つの技術）
    ■ 塩＝体に悪いイメージが強すぎ  ← スライド1枚
      ● 腐らない / 旨みを引き出せる ← そのスライドの行
```

### 🔴 先に測る。書きながら調べない

**元ネタに書いてある事実は、そのまま信じない**。WebSearch で1つずつ確かめる。

- 裏が取れた → そのまま書く
- **裏が取れない** → 行末に `（要確認）`。**消さない**。提案として残す
- **元ネタと食い違った** → **その場で言う**。黙って書き換えない

🔴 **ただし「食い違った」＝こちらが正しい、ではない。**
2026-08-28 に「塩を振っても腐敗は防げない（塩蔵10%以上の話）」と書いたが、
**添削者の「普通に塩をかけるだけでかなり腐敗までの期間が長引く」が正しかった。**
調べ直したら、下味の量でも水分活性が下がって冷蔵3〜5日（無塩1〜2日）。
**指摘されたら、反論する前にもう一度調べる。**

### 書き方

- **スライド1枚 ＝ `## S<番号> <見出し>`**。番号を振ると添削で場所を指せる
- 章の変わり目に `---` を置く
- **1枚に主張は1つ**。表は4行まで。5行を超えたら2枚に割る

### 🔴 話の外枠を語る文を書かない（2026-08-31・全部削られた）

**アジェンダ・まとめ・締めの一文を作った結果、添削で5種類とも消された。**

| 消されたもの | 例 |
|---|---|
| **アジェンダのスライド** | 「今日の3つ」 |
| **まとめのスライド** | 「明日やること」 |
| **締めの一文** | 「肉のうま味は最初から入っている。塩はそれを感じ取れる状態にしている」 |
| **聴衆への語りかけ** | 「〜を3つ持って帰ってもらいます」 |
| 🔴 **見出しの上の小見出し（eyebrow）** | 「振ると何が起きるか」「いちばん聞かれるところ」「結論から」。**9本まとめて削られた** |
| 🔴 **通し番号の隣の章名** | `04 —— SALT` の `—— SALT`。**数字だけ残す** |

**理由：どれも本編で言ったことを言い直しているだけ。**話す人が口で言えばよく、スライドに要らない。

- **章の数を先に予告しない。**章扉が来れば分かる
- **最後にまとめない。**本編が最後の1枚で終わる
- 🔴 **`.note` を「ここまでの要点」に使わない。**note は**本文に無い一段の情報**を足すときだけ
  （「見分け方は〜」「気にするのはひとつだけ」は残った。**言い直しではないから**）
- **比喩を使わない。円数字を使わない**（ターミナルで豆腐になる）
- **句点を太字の外に出す**。`**〜。**次` は閉じない。`**〜**。次` と書く

書き終えたら機械で1つ通す：

```bash
node "${CLAUDE_PLUGIN_ROOT}/skills/slides/scripts/check_bold.js" docs/slides/<なまえ>.md
node "${CLAUDE_PLUGIN_ROOT}/skills/slides/scripts/fix_bold.js" docs/slides/<なまえ>.md   # まとめて直す

# 初回だけ、スクリプトの依存を入れる（node が要る）
npm install --prefix "${CLAUDE_PLUGIN_ROOT}/skills/slides/scripts"
```

### 出すとき

`.md` を渡して、**「直接書き換えてください」と言う。**
添削はコメントではなく**本文の書き換え**で返ってくる。だから次の工程は diff を読むことになる。

🔴 **送ったらコミットする**。次の添削を `git diff` で読むため。
**コミットしていないと差分が取れず、何を直されたか分からない。**

## 2. 添削の読み方

```bash
git diff -- docs/slides/<なまえ>.md
```

**本文に書き込まれた文字が、そのまま指示になっている**。種類を見分ける。

| 書かれ方 | 意味 | どうする |
|---|---|---|
| **`←なんで？`** | **質問。削除指示ではない** | **答えを本文にする**。理由が書けないなら、その行を落とす |
| **`ここまるまるいらない`** | その節ごと削除 | 消す。**惜しんで縮小版を残さない** |
| **`これが一番上に`** | 並べ替え | 順番だけ変える |
| **`←別の言い方`** | 言葉が硬い・伝わらない | **言い換える**。行の主張は変えない |
| **`〜っていうの追加で`** | 行を足す | 足す |
| **`あんまり気にしなくて大丈夫`** | **精密すぎる** | **表を2文に潰す**。選択肢を並べない |
| **`そんなにいらないよ、〜ぐらい`** | 数字が実用と合っていない | **添削者の数字に差し替える**（0.8〜1% → ひとつまみ） |
| **`←これ気持ち悪い。今後こういう言い回ししないで`** | **言い回しそのものの禁止** | その行を消し、**記憶に書く**（次の資料でも繰り返すため） |
| **`（変なサブテキスト入れないで）`** | **こちらが勝手に足した要約文** | 消す。**添削者が書いた文は残す** |
| `（要確認）` が消えている | 承認された | 印だけ外す |

**削られた行は戻さない**。質問に答えた結果、隣の行が要らなくなったら一緒に消す。

🔴 **書き換える前に必ず diff を見る**。先に上書きすると、本文に埋まった指示を読まずに潰す。

### 🔴 「直した」と言われてファイルが変わっていないとき

`stat` で mtime を見る。**保存されていないだけのことがある。**

```bash
stat -f "%Sm %N" -t "%H:%M:%S" docs/slides/<なまえ>.md; date "+now  %H:%M:%S"
```

**変わっていなければ「`⌘S` で保存してください」と言って待つ。**
**推測で「たぶんこう直したいのだろう」と書き換えない。`revert` も勧めない。**

## 3. ビジュアライズ

### 作例を写す

```bash
cp "${CLAUDE_PLUGIN_ROOT}/skills/slides/example/cooking_techniques.html" docs/slides/<なまえ>.html
```

**中身を入れ替えるだけ**。CSS は完成しているので触らない。

🔴 **どのクラスがどの部品か・章ごとに色を変える仕組み・和文で踏んだ穴・ダークで色が反転する罠**は
`${CLAUDE_PLUGIN_ROOT}/skills/slides/css_notes.md` にある。**CSS を書き換えたくなったら、その前に読む。**

### 🔴 1枚ずつ描画して、自分で見る

```bash
node "${CLAUDE_PLUGIN_ROOT}/skills/slides/scripts/deck_shot.js" docs/slides/<なまえ>.html <出力先> [--dark] [--only=3,7]
```

🔴 **初回だけ、描画用のブラウザを入れる**（`node` と合わせて2回で終わる）：

```bash
npm install --prefix "${CLAUDE_PLUGIN_ROOT}/skills/slides/scripts"      # 依存ライブラリ
npx playwright install chromium   # 描画用のブラウザ本体
```

`Chromium が見つかりません` と出たら、これを実行していない。別の場所に入れている場合は `PLAYWRIGHT_CHROMIUM_PATH` に実体のパスを入れる。

**1440×810（16:9）で、`.slide` を1枚ずつ撮る**。プロジェクタと同じ比率。

- **全枚数を撮って、全部 Read で開く。**「たぶん大丈夫」で出さない
- 🔴 **`--dark` は「数枚」ではなく全枚見る。**片方だけ確認して出したら、添削で見つかった（2026-08-31）
- 見るのは **文字が枠から出ていないか / 折り返しが変な位置で割れていないか / 下半分が空きすぎていないか**
- **章扉の下半分が空くときは `.sub` に1行足す**。その章の要約を書くと、扉が扉として成立する。

### 出す

```
Artifact で publish（favicon は題材の絵文字1つ・title は短い名詞句）
```

**リンクと一緒に「`←` `→` で送れます」を伝える**。キー操作は仕込んであるが、言わないと気づかれない。

### 🔴 共有リンクは古い版に固定されたままになる（2026-08-31 実測）

**再公開しても、共有リンクの固定先は自動で更新されない。**
本人の画面では最新が見えるのに、**リンクを踏んだ他の人には古い版が出る**。

- 症状は「別のPCで見たら直っていない」。**ダークモードなど別の条件のせいに見えるので誤診しやすい**
- 確かめ方：`WebFetch` で公開ページを取る。**ヘッダに `viewers see a pinned earlier version, not this live version` と出たら固定されている**
- 🔴 **ツールからは固定先を変えられない。**ページの共有メニューで、共有する版を最新に更新してもらう
- **何度も直したあとは、渡す前にこれを確認する。**「直したはず」で終わらせない

## 4. 片付け

1. `（要確認）` が0件になったら、冒頭の説明行も消す
2. **`.md` と `.html` の文言を揃える**（`node "${CLAUDE_PLUGIN_ROOT}/skills/slides/scripts/drift.js" <md> <html>`）
3. ブランチを切って PR にする。**`main` に直接 push しない**（各自のマシンの hook が止める。止まるのが正常）

## やらないこと

| | なぜ |
|---|---|
| **構成の OK を待たずに HTML を書く** | 構成が変わると全部作り直し。**手戻りがいちばん大きい工程** |
| **元ネタの事実を確かめずに清書する** | 調べずに埋めた行は、あとで全部消すことになる |
| **指摘に反論する前に調べない** | 添削者の実感のほうが正しいことがある（塩と腐敗） |
| **1枚に情報を詰める** | 表が5行を超えたら割る。**登壇者は1枚を20秒しか映さない** |
| **撮らずに publish する** | 検算が通っても見た目は別 |
| **設計の選択肢を並べて選ばせる** | 決めるのは Claude の仕事。**聞いていいのは依頼者しか知らない事実だけ** |
